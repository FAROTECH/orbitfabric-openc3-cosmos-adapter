# Example 01 - Scenario Verification Projection

This is the smallest consumer-facing product example for the OpenC3 COSMOS adapter.

It demonstrates one coherent OrbitFabric-to-COSMOS projection path:

```text
reference Mission Model
    -> Core Integration Input Set
    + OrbitFabric Scenario
    + OpenC3 COSMOS Projection Profile
    -> installed adapter through Adapter Manager
    -> verification_projection
    -> Verification Projection Plan
    -> COSMOS Python procedure / suite
    -> Core-conformant Integration Result
```

## Prerequisites

- OrbitFabric Core installed;
- this adapter installed through OrbitFabric Adapter Manager;
- the installed adapter instance id.

The example does not require an editable adapter install and does not invoke the direct `orbitfabric-openc3-cosmos` contributor CLI.

## Run

```bash
bash examples/01-scenario-verification-projection/run.sh \
  "$ORBITFABRIC_ADAPTER_INSTANCE_ID"
```

An optional second argument selects the generated output directory:

```bash
bash examples/01-scenario-verification-projection/run.sh \
  "$ORBITFABRIC_ADAPTER_INSTANCE_ID" \
  /tmp/orbitfabric-cosmos-example
```

## Authored inputs

```text
mission/
    self-contained OrbitFabric reference mission

scenario.yaml
    stop payload acquisition, then expect inactive telemetry

profile.yaml
    map the OrbitFabric command and telemetry identity to OFDEMO COSMOS names
```

The reference mission is aligned with the exact OrbitFabric Core baseline pinned by this adapter.

## Generated outputs

```text
core-input/
    Integration Input Set generated by Core

projection/integration_result.json
projection/verification_projection/verification_projection_plan.json
projection/verification_projection/cosmos/verification.py
projection/verification_projection/cosmos/verification_suite.py
verify.json
execution.json
```

Generated output is disposable and should not be committed.

## What this proves

The example proves that a consumer can use an adapter instance installed through Adapter Manager to project authored OrbitFabric verification intent into native COSMOS Python artifacts without using the adapter source tree as the execution backend.

Permanent CI executes this same example after installing a built wheel and removing `src/` from the checkout.

## What this does not prove

This example does not start an OpenC3 COSMOS runtime and does not claim live command/telemetry acceptance.

That separate downstream-native gate is owned by:

```text
tools/run_native_cosmos_acceptance.sh
```

Keeping these evidence layers separate prevents a source-level projection example from being presented as runtime acceptance.
